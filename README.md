# مناوب

صفحة ثابتة تعمل على GitHub Pages. يرى الزائر أسماء الموظفين فقط؛ يفتح الموظف سجله برمزه الفردي، بينما يستطيع الأدمن المعتمد إدارة سجلات الفريق.

## ملفات المشروع

- `index.html`: هيكل الصفحة وترتيب تحميل الملفات.
- `app.css`: تصميم الواجهة والتقويم والرصيد.
- `app-core.js`: بيانات الموظفين المحلية، عرض القائمة، وحساب دورة الشفتات.
- `employee-features.js`: استحقاق الإجازة، الرصيد المتوقع، والتقويم والعطلات الرسمية.
- `cloud-config.js`: عنوان Supabase ومفتاح النشر العام. لا تضع فيه مفتاحاً سرياً أو `service_role`.
- `cloud-sync.js`: تسجيل الأدمن، التحقق من رموز الموظفين، وإخفاء سجل الموظف تلقائياً بعد فترة.
- `supabase/schema.sql`: فصل دليل الأسماء عن السجلات الخاصة، وترحيل البيانات القديمة دون حذف الأعمدة السابقة، وسياسات RLS ووظائف التحقق من الرموز.

## نموذج الخصوصية

- جدول `employees` يعرض `id` و`name` فقط لمستخدمي الموقع.
- تفاصيل الموظف محفوظة في `employee_private` ولا تقرؤها الواجهة العامة مباشرة.
- الرمز الفردي لا يُحفظ كنص؛ تخزن قاعدة البيانات بصمته وتعيد سجل موظف واحد فقط عند التحقق.
- الأدمن المعتمد يستطيع تعيين رمز جديد أو إعادة تعيينه. يظهر الرمز له مرة واحدة بعد التعيين.
- سجلات النسخة القديمة تُنقل إلى الجدول الخاص. تبقى الأعمدة القديمة محفوظة لكن لا تمنح الواجهة صلاحية قراءتها.

## ترتيب تحميل JavaScript

يجب أن يأتي `app-core.js` أولاً، ثم `employee-features.js`، وبعدهما إعداد Supabase ومكتبة Supabase، وأخيراً `cloud-sync.js`.

## أين أعدل؟

- ألوان الصفحة وأحجامها: `app.css`.
- معلومات الموظف ودورة 14/14 وعرض الشفتات: `app-core.js`.
- حساب الإجازة والعطلات والتقويم: `employee-features.js`.
- تسجيل الدخول وربط قاعدة البيانات: `cloud-sync.js`.

بعد تغيير ملف JavaScript أو CSS، حدّث قيمة `v=` في رابطه داخل `index.html` حتى يحصل المتصفح على النسخة الجديدة.
